# banco-questoes-pp — M2.5 Design: OAB 1ª-fase objective provas

**Date:** 2026-08-09 · **Status:** approved, pending implementation plan
**Supersedes:** the deferral row in `docs/superpowers/plans/2026-08-08-banco-questoes-pp-m2.md:339`

---

## 1. Why this is being revisited

M2 deferred the 1ª-fase objective provas in a single table row, which is the whole of M2.5's
charter as written:

> **1ª-fase objective provas** — The professor scoped M2 to the 2ª fase. Needs two-column
> coordinate reflow, bold-numeral segmentation, per-exam alternative markers (`A)` vs `(A)`)
> and a glyph-health gate — the 42º Tipo 1 is confirmed mojibake. Triples the parser work for
> the format ranked lowest. Revisit as M2.5.

M3 then built a column-aware extractor, an A–E prova segmenter and two answer-grid readers for
Cebraspe, MPRS and MPF — without noticing that this retired most of M2.5's blockers. Three of the
four named requirements no longer hold.

Note also that **`M2.5` does not appear in `SPEC-questoes-pipeline.md`.** The spec puts multiple
choice in scope v1 (§2) and registers `prova_1a_fase` as an artifact kind for the FGV adapter (§6).
M2.5 is a plan-level deferral, so completing it closes M2's original spec scope rather than adding
new scope.

## 2. Evidence

All rows below were measured on 2026-08-09 by running the repository's own code against the
**43º Exame de Ordem, Caderno Tipo 1 (2025)** and its *Gabaritos Definitivos*, both fetched through
`harvest/http.py` with the configured user agent and 1.5 s spacing.

| M2's stated blocker | Measured reality |
|---|---|
| Two-column coordinate reflow | **Retired.** `extract_columns(body, columns=2)` recovers 80/80 questions and 320/320 `(A)`–`(D)` markers in reading order. |
| Glyph-health gate | **Already built.** `text_health` returns `ok` on both PDFs; it already gates `generic_pdf`. |
| Per-exam alternative markers `A)` vs `(A)` | **Does not apply to this document class.** The OAB uses `(A)`–`(D)`, which the existing `_CHOICE` matches unchanged. |
| Bold-numeral segmentation | **Real, and the only true parser gap.** The OAB anchors questions on a bare numeral alone on its own line — `Questão N` scores 0 hits, `N.`/`N)` scores 0 hits — so `segment_objetiva` returns 0 items. Font weight is not needed to solve it. |

Two further measurements:

- Patching `_ITEM` to `^[ \t]*(\d{1,3})[ \t]*$` and re-running the untouched `segment_objetiva`
  yields **80 items, all usable, numbered contiguously 1–80**. The existing longest-sequential-run
  arbiter correctly discards the trailing 10-item *questionário de percepção*.
- A prototype banded-grid reader recovers **80/80 entries** for Tipo 1, with items 1 and 74
  correctly detected as annulled from the `*` token — which is already in `ANNULMENT_TOKENS`.

### Source availability

Discovery needs **no reconnaissance**. The OAB exam index pages are already in `data/raw/oab` from
M2; `select_penal_padroes` simply filtered the 1ª-fase artifacts out. Counted offline across the 47
cached index pages, 45 of which carry 1ª-fase artifacts:

- **29 exams** publish a `Caderno de Prova - Tipo N`; **19 of those are 2019 or later**.
- All 19 post-2018 exams publish a 1ª-fase gabarito. **10 (2023–2026) publish a *definitivo*;
  9 (2019–2022) publish only a *preliminar*.**

This decouples M2.5 from the separately-unbuilt "Source widening" milestone: same host, same
adapter family, same etiquette, no hand-verified URLs.

### What does not exist

No 1ª-fase fixture, selector, grid style, or test. `harvest/oab_site.py` has no objective path at
all.

## 3. Scope decisions

| Decision | Choice | Rationale |
|---|---|---|
| Which exams | **2019–2026 only** (19 exams, Tipo 1) | `eduagarcia/oab_exams` already covers 2010–2018, so this is the genuinely new material; it also side-steps cross-source overlap entirely, and every question is post-*Pacote Anticrime*. |
| Which tipo | **Tipo 1 only** | Tipos 2–4 are shuffled reshuffles of the same items. Taking one dissolves the tipo-binding and cross-tipo dedup problem M3 deferred for MPRJ/TJRJ. |
| Preliminary gabaritos | **Ingest, auto-flagged** | A preliminary key is what the *recursos* phase overturns. Marking rather than dropping keeps 9 exams while making the caveat visible at pick time. |
| Non-criminal questions | **Keyword pre-gate at ingest** | Each caderno is 80 questions across seven disciplines with no discipline headings to bind on. Without a gate, ~1,350 irrelevant items enter the corpus and the classify bill. |

### Non-goals

- Tipos 2, 3 and 4, and the *tabela de correspondência* that maps between them.
- Exams from 2018 and earlier.
- Backfilling `answer_key_provisional` onto the Cebraspe source that needs it (see §5.4) — the
  mechanism ships here, the retrofit is its own change.
- Any change to `harvest/oab_site.py`'s padrão path (see §4).
- Any change to `[ranking]` weights (see §7).
- A word-clustering column splitter. M3 forbade building it speculatively; midpoint cropping is
  measured sufficient for this document class too.

## 4. Architecture

Four files change, one is new.

```
parse/objetiva.py    (edit)  + item_style selector; + "banded" grid reader
harvest/oab_1f.py    (new)   discovery, Tipo-1 selection, pairing, keyword gate, ingest
vet.py               (edit)  + gabarito_preliminar reason, escalates ok -> flagged
db.py                (edit)  + MIGRATIONS entry: questions.answer_key_provisional
config/sources.yaml  (edit)  + oab-1f-penal source entry
```

The split respects the standing invariants: `parse/` stays pure (text in, dataclasses out), the new
adapter owns source-specific knowledge, `db.py` remains the only module emitting SQL, and `cli.py`
is untouched because this adds a source, not a stage.

Discovery is **imported, not rewritten**. `parse_exam_ids`, `parse_exam_index`, `IndexEntry` and
`normalise_url` in `oab_site.py` are already pure and carry no padrão-specific assumptions.

### Two deliberate non-changes

**`oab_site.py` keeps `extract_text` for padrões.** An earlier review proposed switching it to
`extract_columns`. That would be a regression risk for no benefit: `extract_columns(columns=1)` is
not equivalent to `extract_text` — it applies `x_tolerance=1.5` and strips Unicode `Cf` characters —
so it would silently re-cut all 139 shipped M2 questions. The padrões are single-column and parse
correctly today.

**`[ranking]` is not edited.** New items are `mcq4`, already at the floor weight of 1.0 against
`dissertativa`'s 3.0. The crowd-out concern is handled by config that already exists.

## 5. Component design

### 5.1 `parse/objetiva.py` — selectable item anchor

```python
_ITEM_STYLES = {
    "punctuated": re.compile(r"^[ \t]*(\d{1,3})[ \t]*[\.\)][ \t]+(?=\S)", re.M),  # today
    "bare":       re.compile(r"^[ \t]*(\d{1,3})[ \t]*$", re.M),                   # OAB
}

def segment_objetiva(
    text: str, *, furniture: list[str] | None = None, item_style: str = "punctuated"
) -> list[ObjetivaItem]
```

The anchor is **selected, never widened**. A bare-numeral pattern is far looser than `N.`/`N)` and
would destabilise MPRS and MPF, which parse correctly today. The default preserves current
behaviour exactly, and an unknown `item_style` raises rather than falling back.

`_question_marks` and `_RESYNC_WINDOW` need no change — the longest-sequential-run arbiter already
resolves the OAB caderno to exactly 1–80.

### 5.2 `parse/objetiva.py` — the banded grid reader

```python
def read_grid(text: str, *, style: str, section: str | None = None) -> dict[int, str | None]
```

The OAB gabarito is a *banded transpose*: a row of up to 20 item numbers, then a row of the same
many letters directly beneath. Neither existing style reads it — both raise `GridError`, correctly
refusing to guess.

Critically, **one file carries all four tipos**. An unscoped banded read would let Tipo 4's row
overwrite Tipo 1's and ship four-fifths wrong answer keys. Therefore:

- `style="banded"` **requires** `section`; `GridError` is raised when it is absent.
- `GridError` is raised when `section` matches nothing.
- The block is bounded by the next heading of the same shape.
- Head and answer rows are zipped with `strict=True`; a length mismatch raises.
- The recovered numbers must be contiguous, reusing `_read_interleaved`'s existing check.
- `*` maps to `None` via the existing `ANNULMENT_TOKENS`.

`section` is passed by the adapter, not hardcoded, so the reader stays source-agnostic.

### 5.3 `harvest/oab_1f.py`

```python
@dataclass(frozen=True)
class Artifacts:
    caderno: IndexEntry
    gabarito: IndexEntry
    definitivo: bool

def select_1f_artifacts(entries: list[IndexEntry], *, tipo: int = 1) -> Artifacts | None
def is_criminal(item: ObjetivaItem, keywords: list[str], min_hits: int) -> bool
def ingest_caderno(caderno_text, gabarito_text, *, exam, artifacts, source_id, db,
                   params, force=False, seen=None) -> int
def harvest_source(entry, db, settings, *, dry_run=False, force=False, offline=False) -> int
```

`select_1f_artifacts` prefers a *definitivo* gabarito and falls back to the newest *preliminar*,
mirroring `select_penal_padroes`'s existing definitivo-preference. It returns `None` when either
artifact is missing, so the exam is skipped rather than half-ingested.

`is_criminal` scores **the stem plus all four alternatives**, never the stem alone — the same rule
already applied to comando and rationale elsewhere. It is a recall/hygiene trade, so the keyword
list is generous config, and every exam logs how many items it dropped. No silent truncation.

**Network cost:** the 47 index pages are already cached, so only 38 new PDFs are fetched
(19 cadernos + 19 gabaritos), roughly one minute at 1.5 s spacing.

### 5.4 Provisional answer keys

`Question` gains `answer_key_provisional: bool = False`, backed by one guarded migration:

```python
MIGRATIONS = (
    ("questions", "stem_context", "TEXT"),
    ("questions", "answer_key_provisional", "INTEGER DEFAULT 0"),
)
```

`vet.py` gains a rule patterning the existing `no_gabarito` escalation:

```python
if question.answer_key_provisional:
    reasons.append(VetReason(code="gabarito_preliminar",
                             detail="gabarito preliminar, sujeito a alteração após recursos"))
```

`_merge_verdict`'s hardcoded `no_gabarito` check becomes a set membership test over
`_ESCALATING_CODES = {"no_gabarito", "gabarito_preliminar"}`, so `ok` escalates to `flagged`.

This flag pays for itself beyond M2.5. The existing Cebraspe source `PC_DF_26_DELEGADO` is
published as *"PROVA OBJETIVA (P1) E GABARITO PRELIMINAR COM JUSTIFICATIVAS"* and carries the same
exposure today, unmarked.

**Setting the flag on that source is deliberately out of M2.5's scope.** It is a Cebraspe-adapter
change, and folding it into an M2.5 task would let this milestone rewrite M3's rows. The mechanism
lands here; applying it to Cebraspe is a separate one-commit change whenever the professor wants it.
`config/sources.yaml`'s `cebraspe-cadernos` entry gains a note recording the exposure so it is not
rediscovered later.

The ranking consequence is automatic and correct: a flagged item forfeits `vet_ok_bonus` (2.0), so
preliminary-key questions sink within their subtopic without any weight tuning.

`curate` needs no change: `curate.py:112-117` already renders, for any flagged question, both the
reason codes and each reason's detail line under the ⚠ **Sinalizada** banner. The professor will
therefore see *gabarito preliminar, sujeito a alteração após recursos* at pick time for free.

`grid_section` is formatted with the entry's own `tipo` before use, so changing `tipo` cannot leave
the section regex pointing at a different prova.

Adding or retuning the gate is a config edit, not a code change.

## 6. Data flow

```
seed page -> exam ids -> index page (cached) -> select_1f_artifacts (Tipo 1 + best gabarito)
  -> filter to exam_year >= 2019
  -> fetch caderno, gabarito
  -> extract_columns(caderno, columns=2) ; extract_columns(gabarito, columns=1)
  -> text_health gate  ................................. 42º-style mojibake exits here
  -> segment_objetiva(item_style="bare")               -> 80 items
  -> read_grid(style="banded", section=r"PROVA\s+TIPO\s+1\b")
  -> is_criminal() gate                                -> ~1,350 non-criminal dropped
  -> Question(format="mcq4", answer_key_provisional=not definitivo)
  -> classify -> vet -> curate                          (all unchanged)
```

`exam_year` comes from the index entry date, which is load-bearing: without it the law watchlist
cannot fire for this source.

Annulled items need no special handling — `nullified=True` already short-circuits to a terminal
`rejected` in `vet.apply_rules`, so they never reach a shortlist.

## 7. Error handling

Every failure is per-exam or per-item and never abandons the run, matching the existing stage-loop
contract.

| Condition | Action |
|---|---|
| Missing caderno or gabarito | INFO, skip exam |
| `text_health != "ok"` | WARNING, skip exam |
| `GridError` | ERROR, skip exam — never default a key |
| 0 items segmented | WARNING, skip exam |
| Item number absent from grid | INFO, skip item |
| `FetchError` | ERROR, continue to next exam |
| Keyword gate drops | INFO count per exam |

## 8. Testing

Fixtures are pdfplumber-extracted **text**; no PDFs are committed, per the standing convention and
`.gitignore`.

**`tests/test_objetiva.py`**
- `item_style="bare"` segments the OAB fixture into contiguous items with four choices each.
- **Regression:** the default style leaves the MPRS and MPF fixtures byte-identical.
- An unknown `item_style` raises.
- The banded reader recovers a full grid and maps `*` to `None`.
- `style="banded"` without `section` raises `GridError`.
- `style="banded"` with an unmatched `section` raises `GridError`.
- Misaligned head/answer rows raise `GridError`.
- **The gabarito fixture retains all four tipo blocks**, so scoping is tested against the real
  failure mode rather than a synthetic one — a Tipo 1 read must not return Tipo 2–4 letters.

**`tests/test_oab_1f.py`**
- `select_1f_artifacts` prefers definitivo; falls back to preliminar; returns `None` on a missing
  artifact; selects the requested tipo and not its siblings.
- `is_criminal` keeps a processo-penal item and drops a tributário one.
- `ingest_caderno` writes the expected count and sets `answer_key_provisional` from
  `Artifacts.definitivo`.
- An exam whose text layer is unhealthy is skipped without writing rows.

**`tests/test_migration.py`**
- Open a database created at M3's schema, migrate, assert the new column exists and defaults to 0.

**`tests/test_vet.py`**
- `answer_key_provisional` escalates `ok` to `flagged`.
- `rejected` stays `rejected`.
- A nullified item is still terminally `rejected`.

Tests touch neither the network nor an LLM.

## 9. Task 0 — recon sweep

All measurements in §2 are **n = 1** (43º Exame, 2025). The M2 plan records that *"the 42º Tipo 1 is
confirmed mojibake"* — an adjacent exam that already fails. Older exams may differ in anchor style,
column geometry and alternative count.

So the implementation plan opens, as M2 and M3 did, with a sweep across all 19 in-scope exams
reporting per exam: `text_health`, item count and contiguity, grid entries, item↔grid match rate,
and keyword-gate yield. That sweep produces the **spec-amendments table verified against live
sources** the plan docs use, fixes the real yield number, and populates `keep_keywords`.

Exams that fail are logged by name and excluded — the precedent being M2 shipping 35 of 45 exams
rather than building speculative parsers for the other 10.

## 10. Success criteria

- The 19 in-scope exams are swept; every exclusion is logged by name with its reason.
- `bqpp harvest` is idempotent for this source: a second run writes zero new rows.
- No shortlist entry carries a Tipo 2–4 answer key.
- Every ingested question has an `exam_year`, so the law watchlist can fire.
- Preliminary-key questions surface as `flagged` with the `gabarito_preliminar` reason visible.
- MPRS, MPF and Cebraspe output is unchanged — verified by fixture equality, not by inspection.
- Full suite green with no network and no LLM; `ruff check .` clean.

## 11. Open risks

| Risk | Mitigation |
|---|---|
| **n = 1.** Only the 43º is verified. | Task 0 sweeps all 19 before any parser is finalised. |
| **Keyword-gate recall.** A generous list still drops real criminal-procedure items. | Task 0 measures the gate against a hand-checked exam; the list is tunable config; drops are logged, never silent. |
| **Asymmetric gutters.** An off-centre column split produces mid-word splices that `text_health` still rates `ok`. | Task 0 inspects extracted stems per exam; a failing exam is excluded rather than ingested corrupt. |
| **Yield is extrapolated.** ~100–170 criminal items is derived from one exam (5 clearly processo penal, 8 penal-material of 80). | Treated as an estimate until Task 0 reports; the milestone is not sized on it. |
